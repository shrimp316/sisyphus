# G123의 무강화 통과 불가능 상한과 성장 후 통과 증거

이 문서는 **실험 후보 G123에만** 적용된다. 기존 게임 및 A/B/C 후보의 실패를 물리적 불가능으로 바꾸어 해석하지 않는다. 유한한 자동 정책 탐색의 실패를 증명으로 사용하지 않는다.

## 적용 조건

- 경로 750~873m의 연속 123m: 45° `STONE`, 접지 1, 구름 저항 0.2.
- 청크 15·16의 오르막은 50m, 청크 17은 23m. 세 청크에 `wet_ranges: []`를 명시하여 비에서도 게이트 노면이 변하지 않는다.
- 게이트 내부 쉼터·돌턱·받침·구매 기회 없음. 게이트 밖에 실제 쉼터가 있다.
- 게이트 내부 입력 해제 회복 0. 정지 직전 7/s 회복도 포함해 차단한다. 쉼터 정지 회복은 유지한다.
- 기존 120Hz 적분, 추진·힘주기·버티기, 스태미나 계층, Slip·Runaway 판정을 그대로 사용한다. 랭크 조건을 검사하여 통과를 막는 코드는 없다.
- 진입 스태미나 ≤ 현재 최대치, 전진 속도 ≤ 1.8m/s. 게이트 안에서 성장·상태를 외부에서 변경하지 않는다.

실제 배치가 위 조건인지 `verify_instrumentation.gd`가 시드1001~1100 × 맑음/비에서 검사한다. 증명의 구조적 조건은 설정 코드에서도 직접 확인한다. 현재 production controller의 SHA-256은 `30a312b144383be64fc6fe35b8ad107ebba9a90672d9dda941f9ef8018279944`다. 생성 컨트롤러는 이 해시와 세 문자열 삽입 지점을 검증한다.

## 1. 이산 적분에 대한 위치·운동에너지 상한

게이트의 중력 `g=3 sin(45°)`와 저항 `r=0.2`에 대해 `c=g-r=1.92132034355964 > 0`으로 둔다. 실제 전진 저항은 보통 `g+r`이므로 `c`는 플레이어에게 유리한 보수적 하한이다. 위치 `x`, 전진 속도의 양의 부분 `v+=max(v,0)`에 대해 다음 잠재량을 사용한다.

`H = c*x + (v+)²/2`

한 스텝에서 실제 추진력 `F`, 스텝 뒤 속도 `v'`에 대해:

`H' - H ≤ F * max(v',0) * dt`

이 부등식은 다음과 같이 얻는다.

- `v'>0`인 일반 적분에서는 가속도가 `F-c` 이하이고, 코드는 **새 속도**로 위치를 갱신한다. `ΔK = a*v'*dt - (a*dt)²/2`의 마지막 항은 음수다. 속도 상한은 운동에너지를 더 늘리지 않는다.
- 이전 속도가 음수였다가 전진으로 돌아오면 양의 운동에너지는 0부터 시작한다. `v' ≤ (F-c)dt`이므로 같은 부등식이 유지된다.
- 스텝 뒤 속도가 0 이하이면 위치와 양의 운동에너지는 증가하지 않는다. 버티기는 양의 속도를 만드는 순간 0으로 제한되므로 외부의 전진 에너지 공급원이 아니다.
- Slip은 전진 관성을 제거하고 아래 방향 충격을 준다. 양의 운동에너지를 늘리지 않는다. Slip 발생 스텝의 추진력은 0이다.

따라서 후퇴, 전진·후퇴 반복, 임의의 키 조합, 120Hz보다 긴 입력 유지 등을 모두 허용해도 이 상한은 유지된다. 한 번 왼쪽 쉼터로 돌아가 회복한 뒤 다시 시도한다면, 최종적으로 오른쪽을 통과하는 **마지막 진입 이후의 구간**에 같은 상한을 적용하면 된다.

## 2. 모든 속도·입력 조합의 스태미나당 공급 상한

성장 추진 배율을 `P`, 게이트 소비 배율을 `q=1.7`, 스태미나 추진 계수를 `ρ(S)`로 둔다. 계수는 잔량 비율에 따라 1, 0.85, 0.65, 0이다.

속도 구간별 실제 코드의 추진·소비 배율을 사용하되, 다음 속도는 `min(1.8, 구간 상한 + 최대추진력*dt)`로 과대평가한다. 중력과 저항을 여기서 생략하는 것은 플레이어에게 유리하다. 모든 일반 밀기·힘주기 구간에서 다음을 계산해 최댓값을 취한다.

`R = max[ F0 * min(1.8, v_band_upper + F0*dt) / drain0 ]`

`F0`는 해당 속도·입력의 `ρ=1` 추진력이다. 속도 구간 상한은 0.45, 1.2, 1.5, 1.8이고, 적정 속도 구간은 추진×1.1·소비×0.8, 고속 구간은 추진×0.9다. 힘주기는 추진×1.65·소비×3이다. 후퇴 시 힘 전달 감소는 무시하여 공급량을 더 크게 잡는다.

무강화에서 최대는 적정 속도 일반 밀기이며:

`R = 2.86 * (1.2 + 2.86/120) / (0.8*1.7) = 2.57364950980392`

실제 스태미나 계수 `ρ≤1`에 대해 공급량은 `R*ρ*스텝 소비량` 이하다. 게이트 안에는 회복이 없으므로 스태미나는 단조 감소한다. 전체 계층 적분은:

`∫ρ(S)dS = capacity * (0.5 + 0.3*0.85 + 0.2*0.65) = 0.885*capacity`

이산 스텝은 경계 통과 후의 잔량에 대해 한 스텝 더 높은 계수를 사용할 수 있다. 50%·20%·0 경계의 계수 차이 합은 1이고, 추진 한 스텝 최대 소비는 `3*q*dt`다. 마지막 스텝의 잔량 초과 소비까지 포함하여:

`Σ ρ*추진소비량 ≤ 0.885*capacity + 3*q*dt`

Slip 손실과 버티기 소비는 추진 공급량을 늘리지 않으며, 남은 예산만 줄인다. 따라서 누락한 손실을 포함하지 않아도 상한으로 유효하다.

## 3. 무강화 결과

최대 진입 운동에너지 `1.8²/2=1.62`를 모두 인정한다. 경계 직전 스텝이 게이트 안으로 최대 `1.8/120=0.015m` 들어올 수 있으므로 필요한 거리를 122.985m로 줄여준다.

- 최대 공급 예산: `R*(88.5 + 3*1.7/120) + 1.62 = 229.497361721814`
- 최소 필요량: `c*(123 - 1.8/120) = 236.293582452683`
- 부족량: **6.796220730869**

필요량보다 유리하게 잡은 공급 상한조차 작다. 따라서 위 조건의 **무강화 G123은 임의의 일반 입력 전략으로 통과할 수 없다.** 이것은 특정 자동 정책의 실패와 다른, 소스 방정식 수준의 불가능 상한이다. 스태미나 계층과 이산 스텝을 생략한 연속계 근사 결과가 아니다.

이 증명은 정리 증명기로 검증한 IEEE 부동소수점 프로그램의 형식 증명은 아니다. 소스 대조, 해시 고정, 세대별 동등성 검사와 1,120개 입력·상태 경계의 부등식 검사를 함께 제공한다. 출력 소수점은 계산 편의상 반올림된 값이며, 계산 반올림과 비교해 충분히 큰 부족량이 있다. 조건을 바꾸면 증명을 다시 계산해야 한다.

## 4. 성장 후 가능한 경로는 별도 실행으로 확인

상한이 넉넉하다는 사실만으로 통과 가능을 주장하지 않는다. `verify_gate_bound.gd`는 실제 컨트롤러에 **진입 상태 fixture**를 넣고, 이후에는 키 입력만으로 진행한다. 초기 위치750m·최대 스태미나·속도1.8m/s를 제공하므로 전체 등반의 통과율과 구분해야 한다.

목표 속도1.195m/s에서 정상 밀기와 관성 이동을 120Hz로 선택하고, 정상 추진력이 부족하거나 출발 속도가 낮으면 힘주기를 사용한다. 이는 정확한 물리 정보를 읽는 비현실적 기준 정책이다.

| 힘/최대스태미나/회복 rank | 123m 게이트 fixture 결과 |
|---|---|
| 0/0/0 | 89.586m에서 최고점. 위 불가능 상한은 이 정책과 독립적 |
| 8/8/8 | 120.496m에서 최고점. 이 실패만으로 모든 8/8 입력의 불가능을 주장하지 않음 |
| 9/9/9 | 통과 |
| 10/8/0 | 통과 |
| 8/10/0 | 통과 |
| 10/10/10 | 통과 |

성장 효과는 기존 +2% 강화만 사용한다. 회복 강화는 게이트 내부 회복0에서는 직접 도움이 되지 않는다. 두 다른 힘·최대스태미나 배분의 통과를 확인했지만 모든 빌드에 동등한 효율이 있다는 뜻은 아니다. 실제 0m 출발, 게이트 앞 완전 회복과 진입 속도 확보, XP 획득·구매·추락 후 재도전은 별도 전체 경로 실험에서 확인해야 한다.

실패 후 스태미나가 완전히 고갈된 급경사에서 긴 거리를 안전하게 되돌아오는 것을 보장하지 않는다. 자연 Runaway·추락 후 새 회차로 돌아가는 기존 실패 경로를 허용한다. 이를 ‘게이트 어느 상태에서도 안전하게 후퇴할 수 있다’고 표현하면 안 된다. 강제 Slip, 강제 Runaway, 돌턱 요구 상승, 명시적 랭크 잠금은 사용하지 않는다.
