# 실제 브라우저 검사

2026-10-27, Godot 4.5.1 debug Web export를 `127.0.0.1:8766`에서 Codex 내장 Chromium 브라우저로 실행했다. 정식 사이트에는 접속하거나 배포하지 않았다. 브라우저 입력은 화면의 버튼·키보드로 수행했다.

확인한 항목:

- 메인 화면, 새 게임 확인·진입, D 2.5초/Shift+D 1.5초/Space 1초 입력 후 약 8m 이동, Esc 메뉴와 저장.
- 브라우저 새로고침 후 이어하기 버튼과 8m 위치 복원, Enter로 이어하기.
- 인공 250m 저장의 첫 해금 화면 복원, 35개 노드·연결선·선행/잠금 표시, STR01 확인 구매로 150→120 EXP. 재로딩 후 구매와 안내 유지.
- 1920×1080 및 960×540 창 크기, 실제 디스플레이 1920×1080 전체 화면. 크기 변경 시 캔버스가 부모보다 커지는 현상을 발견해 MVP 전용 셸에 resize policy 2와 CSS 크기 우선순위를 적용했다. 기존 Web 셸은 변경하지 않았다.
- 인공 `PRESTIGE_COMMIT` 저장을 이어하기로 연 뒤 해당 연출 화면에서 실제 reload. 다시 이어하기 후 0m 새 회차, EXP 0·구매 0·프레스티지 1·실 1·말쿠트 활성 확인. 완료 후 다시 reload해 같은 값 유지.
- 설정의 음소거 변경, 설정 저장 복원, 운명의 직조 메뉴와 말쿠트 안내.
- 마지막 게임 페이지의 수집된 error/warn 콘솔 항목 0개.

정상 도달은 `fixtures/web/prestige-commit.json`을 사용하는 **인공 저장 전환 검사**이며 인간이 산을 완주한 증거가 아니다. UI 도구로 `qa.html`의 버튼을 눌러 MVP 전용 localStorage에 fixture를 넣었다. `save-after-reloads.json`은 그 페이지의 읽기 버튼이 표시한 실제 저장 요약이다. 모든 단계별 crash 경계·두 번 프레스티지·2,000 EXP는 별도 native 자동 통합 검사에서 검증했다.

`viewport-emulation-fullscreen-limitation.png`는 성공 증거가 아니다. 브라우저의 960×540 viewport 에뮬레이션과 운영체제 전체 화면을 동시에 적용하면 화면이 사분면에 표시되었다. 에뮬레이션 해제 후 실제 1920×1080 전체 화면은 `board-fullscreen-native.png`처럼 정상이다. 이 조합의 원인을 게임 결함 또는 도구 결함으로 확정하지 않았으며, 실제 저해상도 디스플레이 전체 화면은 미검증이다. 960×540 일반 창에서는 정상 비율이며 웹 페이지의 세로 스크롤을 사용할 수 있다.

Safari/Firefox/모바일·브라우저 저장 용량 부족·OS 전원 손실은 테스트하지 않았다. 원본 PNG 아트와 달리 이 폴더의 PNG는 실행 결과를 기록한 새 스크린샷이다.
