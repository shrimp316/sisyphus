# SISYPHUS · 시지프스

**[브라우저에서 플레이](https://shrimp316.github.io/sisyphus/)** · [GitHub 저장소](https://github.com/shrimp316/sisyphus)

돌을 밀고, 숨을 고르고, 다시 시작하는 2D 물리 게임의 **v0.2 핵심 조작 MVP**입니다. Godot 4.5 이상 / GDScript / Compatibility 렌더러를 사용합니다. 기준 해상도는 1920×1080입니다.

새 [상세 명세 v0.2](docs/game-system-v0.2.ko.md)를 기준으로 관성·부분 추락·돌턱을 먼저 검증합니다. 기존 산 조합과 날씨는 유지합니다. 기억·성장·이벤트·철학 엔딩은 10명 플레이 테스트를 통한 재미 검증 이후 단계로 보류했습니다. 전체 명세의 반영 범위는 [v0.2 반영 안내](docs/v02-alignment.ko.md)에 있습니다.

## 실행

브라우저용 Web 빌드와 GitHub Pages 배포 설정도 포함합니다. PC 키보드로 플레이하며 진행 상황은 해당 브라우저에 저장됩니다. [웹 실행·배포 안내](docs/web-play.ko.md)를 참고하세요.

이 작업 폴더에서는 **`Play.cmd`를 더블클릭**하면 됩니다. 검증용 공식 Godot 4.5.1 엔진이 `.tools/godot/`에 준비되어 있습니다. 이 엔진은 Git에 포함하지 않습니다.

새 물리를 같은 짧은 코스에서 시험하려면 **`DebugPlay.cmd`**를 실행하세요. 일반 등반의 저장과 기록에 영향을 주지 않습니다. 기존 회차를 이어 하는 경우에는 이전 물리가 유지되므로 새 기능을 즉시 시험할 때도 이 코스를 사용할 수 있습니다.

다른 PC에서는 [Godot 공식 사이트](https://godotengine.org/download/)의 Godot 4.5 이상 일반 버전을 설치하고 `project.godot`를 가져온 뒤 **F5**로 실행하세요. .NET 버전이나 외부 플러그인은 필요하지 않습니다.

에디터에서 열기:

```powershell
& '.\.tools\godot\Godot_v4.5.1-stable_win64.exe' --editor --path .
```

## 참가자에게 전달하는 Windows 테스트

`builds/`의 `SISYPHUS-v0.2-Windows-…zip`을 전달합니다. 참가자는 Godot 설치 없이 ZIP 전체를 압축 해제하고 **`Playtest.cmd`**를 실행하면 됩니다. 서로 다른 참가자 번호 01~10을 배정하세요. 연습 코스와 본 코스의 저장이 분리되고, 본 코스 종료 후 응답을 남길 수 있습니다.

응답과 실행 로그는 참가자의 `playtest-results` 폴더에만 저장되며 자동 전송하지 않습니다. 결과를 받은 뒤 [진행·집계 안내](docs/playtest-v02.ko.md)에 따라 정리하세요. 아직 실제 참가자 결과는 없습니다.

[참가자 안내](docs/playtest-participant.ko.md) · [Windows 빌드 방법](docs/windows-playtest-build.ko.md)

## 조작

| 키 | 행동 |
|---|---|
| D 또는 → 유지 | 돌 밀기 |
| 밀면서 Shift 유지 | 힘주기: 더 강한 추진, 더 큰 스태미나 소비와 미끄러짐 |
| 후퇴 중 Space 유지 | 버티기: 스태미나를 소비해 제동 |
| 키를 놓기 | 회복: 경사에서는 돌이 뒤로 굴러갈 수 있음 |
| Esc | 일시정지 / 메뉴 |
| Enter | 시작 / 결과 화면에서 다음 회차 |
| E | 두 번째 추락부터, 최소 연출 시간이 지난 후 건너뛰기 |
| M | 음소거 |
| F11 | 전체 화면 |
| F3 | 개발 빌드에서 물리 디버그 정보 표시 |

평평한 쉼터에서 돌이 멈추면 안전하게 회복할 수 있습니다. 오르막에서 손을 놓으면 중력이 작용합니다. 뒤로 굴러가기 시작했을 때 Space로 붙잡고 다시 밀어 보세요. 새 물리에서 속도가 -4m/s 이하가 되면 돌이 통제를 벗어납니다. 폭주 전에는 홈에 걸려 일부 거리만 잃고 계속 등반할 수 있습니다.

첫 추락은 끝까지 진행되며, 이후에도 최소 1.5초는 추락을 보여 줍니다. 추락은 게임 오버가 아니라 한 회차의 끝입니다. 정상의 전체 거리나 진행률, 최고 기록 숫자는 HUD에 표시하지 않습니다. 이전 최고점에는 작은 돌탑이 남고, Slip은 위험이 쌓일 때만 나타납니다.

0.45~1.2m/s의 적정 속도에서는 밀기·스태미나·균형 효율이 좋아집니다. 정지에서 다시 출발할 때는 더 큰 힘이 필요하고, 지나친 속도는 미끄러짐 위험을 높입니다. 돌턱 앞에서는 관성과 힘주기 타이밍을 함께 판단하세요.

## 달라진 산

수제 구간 15종을 5개 구역의 후보 목록에서 조합합니다. 어려운 구간이 지나치게 이어지지 않도록 배치를 제한하고, 각 구간에는 호흡을 회복할 수 있는 쉼터를 둡니다.

| 지형 | 조작에 미치는 영향 |
|---|---|
| 돌 | 기본 접지력과 구름 저항 |
| 자갈 | 접지력이 더 낮고 힘주기 중 미끄러짐에 주의해야 함 |
| 진흙 | 저속에서 저항이 더 커지므로 관성 유지가 중요 |
| 젖은 바위 | 구름 저항은 작지만 접지력이 낮고 미끄러지기 쉬움 |

맑음과 비 중 하나가 회차 시작 시 결정됩니다. 새 산의 비는 일부 노출된 구간의 젖음과 접지력에 영향을 주며 모든 구간에 균일하게 적용하지 않습니다. 화면의 지형 색·표면 무늬와 날씨 표시를 보고 판단하세요. 날씨 자체가 무작위로 즉사를 일으키지는 않습니다.

비가 오는 급경사에서는 쉼터에서 충분히 회복한 뒤 출발하고, 계속 Shift를 누르기보다 스태미나와 미끄러짐을 함께 확인하는 것이 좋습니다.

## 저장과 재개

Esc 메뉴의 **저장 후 종료** 또는 창 닫기로 종료하면 현재 회차를 저장합니다. 다음 실행에서 **이어 오르기**를 누르면 위치뿐 아니라 속도·스태미나·미끄러짐 상태도 이어집니다. 다른 창으로 이동하면 자동으로 일시정지합니다.

산의 구간 배치와 날씨도 함께 저장합니다. 이전 버전에서 저장한 회차는 당시 산과 물리로 이어 가며, 그 회차를 마친 뒤 새로 시작하면 v0.2 물리가 적용됩니다. 기존 저장 파일을 지울 필요가 없습니다.

Windows 기본 저장 위치는 `%APPDATA%\Godot\app_userdata\SISYPHUS\sisyphus-v1.json`입니다. 강제 프로세스 종료나 전원 차단에는 저장을 보장하지 않습니다. 테스트는 별도 `--save-path`를 사용하므로 플레이 저장 파일을 바꾸지 않습니다.

그래픽과 바람·구르는 소리·추락 충돌음·배경음·빗소리·호흡·발소리는 코드로 생성합니다. 외부 이미지·음원 다운로드가 필요하지 않습니다.

## 프로젝트 구성

- `project.godot`, `main.tscn`: 프로젝트 설정과 진입 장면
- `scripts/`: 경로, 돌 물리, 화면과 회차 제어
- `data/chunks/`: 에디터에서 수정 가능한 수제 구간 Resource 15종
- `tests/`: 헤드리스 물리 및 통합 검증
- `docs/game-system-v0.2.ko.md`: 현재 기준 명세. v0.1도 이력으로 보관
- `docs/v02-alignment.ko.md`: v0.2의 반영 범위와 보류 항목
- `docs/playtest-v02.ko.md`: 10명 플레이 테스트 진행안과 빈 기록표
- `docs/verification.ko.md`: 현재 빌드의 검증 결과와 재현 명령
- `docs/implementation-scope.ko.md`, `docs/environment.ko.md`: v0.1 구현 범위와 환경 수치 이력

물리의 거리(m)와 화면 좌표(px)는 분리되어 있습니다. `mountain_manager.gd`의 수제 구간이 `Curve2D`를 만들고, 돌은 이 곡선의 거리를 따라 움직입니다. 스태미나·밀기·제동·미끄러짐은 `boulder_controller.gd`에서 고정 간격으로 계산합니다.

## 검증

프로젝트 파싱 및 리소스 가져오기:

```powershell
& '.\.tools\godot\Godot_v4.5.1-stable_win64_console.exe' --headless --path . --log-file "$PWD/.tools/import.log" --editor --quit
```

자동화 테스트의 결과와 실행 명령은 `docs/verification.ko.md`에 기록합니다. 실제 손맛과 5~15분 목표 플레이타임은 사람의 플레이 테스트로 추가 조정해야 합니다.

테스트 코스 명령줄 실행:

```powershell
& '.\.tools\godot\Godot_v4.5.1-stable_win64.exe' --path . -- --debug-course --save-path=user://sisyphus-debug-v02.json
```

F3는 개발 빌드에서만 동작합니다. 웹은 Release 빌드로 내보냅니다. 모바일 터치 입력은 아직 지원하지 않습니다.
