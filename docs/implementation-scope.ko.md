# 구현 범위: 핵심 조작과 산·환경

> 아래는 v0.1에 따른 구현 이력이다. 현재 우선순위와 범위는 [v0.2 반영 안내](v02-alignment.ko.md)를 따른다. 기억·성장 개발은 먼저 진행하지 않는다.

원본: [게임 시스템 명세 v0.1](game-system-v0.1.ko.md)

첫 단계는 명세 64번의 플레이 루프를 검증하는 Godot 4 프로젝트다. 두 번째 단계에서는 명세 65번에 따라 수제 구간 조합, 지형, 날씨를 추가한다. 명세의 전체 MVP(63번)와 구분하며, 플레이어가 밀기·힘주기·휴식·버티기를 판단하는 구조를 유지한다.

## 1단계: 핵심 조작

- Path2D / Curve2D 위의 거리, 속도, 가속도로 돌을 제어한다.
- 거리 단위(m)와 렌더링 단위(px)를 명시적으로 변환한다.
- D / →로 밀고, 함께 누른 Shift로 힘을 더한다.
- 후퇴 중 Space로 제동한다. 제동만으로 오르막 추진력을 얻지 않는다.
- 스태미나가 바닥나도 밀기는 가능하지만 효율이 감소한다.
- 미끄러짐은 누적 게이지로 예고한다. 무작위 즉사는 없다.
- 폭주 전에는 회복할 수 있다. 폭주하면 산 아래로 돌아가 회차가 끝난다.
- 첫 추락을 본 이후에만 추락 연출을 건너뛸 수 있다.
- HUD는 현재 거리만 보여 주고 정상까지 남은 거리는 표시하지 않는다.
- 한 산의 정상 도달과 재시작을 구현한다. 최종 철학 엔딩은 후속 단계다.
- 일시정지와 종료 시 임시 저장을 제공한다. 중간 체크포인트는 만들지 않는다.

## 2단계: 산과 환경

- Godot Resource로 정의한 수제 Chunk 15종을 5개 구역의 후보 목록에서 조합한다.
- 돌·흙·자갈 3종의 접지력, 구름 저항, 미끄러짐 차이를 물리에 반영한다.
- 회차마다 맑음 또는 비를 선택한다. 날씨는 회차 중 바뀌지 않는다.
- 무작위로 산의 모양을 그리지 않는다. 준비된 구간을 조합하고 고난도 구간의 연속을 제한한다.
- 빗길에서도 기본 능력으로 오를 수 있도록 급경사 길이와 쉼터를 함께 조정한다.
- 지형은 색과 표면 무늬로 구분하며 현재 지형과 날씨를 HUD에서 알린다.
- 저장에는 산의 구간 배열과 날씨를 포함한다. 이어 할 때 산을 다시 뽑지 않는다.
- 이전 버전의 저장은 기존 산과 물리로 회차를 이어 가고, 다음 회차부터 새 산을 사용한다.
- 카메라와 미끄러짐 게이지는 기존 기능을 유지하고 비와 지형에 맞춘 소리를 추가한다.

## 후속 단계

1. 플레이 테스트로 핵심 15초의 재미를 확인하고 힘, 제동, 회복, 미끄러짐 수치를 조정한다.
2. 기억 보상, 반복 파밍 감소, 스탯 3종, 업그레이드 8종을 추가한다.
3. 이벤트 8개, 철학 4개, 반복 대사, MVP 엔딩 2개를 추가한다.
4. 장기 플레이 검증 후 전체 엔딩과 진엔딩을 구현한다.

## 설계상 주의점

명세의 힘주기 소비량(초당 -4와 배율 ×3), POWER 시작값(레벨 1이 ×1.00인지 ×1.08인지)은 서로 일치하지 않는다. 이 단계에서는 물리 코드의 상수를 실제 기준으로 삼고, 성장 시스템을 추가할 때 레벨 0/1 기준을 확정한다.

`distance`는 경로를 따라 이동한 거리다. 화면 표시는 이 값을 사용하며, 지형의 수직 높이와 동일하지 않다. 정상 길이는 플레이 UI에 노출하지 않는다.

자동화 검증은 상태 전이와 물리 일관성을 확인한다. 재미, 피로감, 목표 회차 시간은 실제 플레이 테스트가 필요하다.
