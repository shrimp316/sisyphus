# v0.2 명세 반영 범위

기준 문서는 [상세 구현 명세 v0.2](game-system-v0.2.ko.md)다. v0.1과 충돌하면 v0.2를 우선한다. 앞선 작업의 '2단계 완료'는 v0.1 개발 순서의 산·환경 구현을 뜻하며, v0.2의 MVP 재미 검증 완료를 뜻하지 않는다.

## 이번 구현

새 명세 106·111·112번의 핵심 조작 MVP를 보강한다.

| 변경 | 목적 |
|---|---|
| 적정 속도, 출발 페널티, 고속 위험 | 최대 속도보다 힘 조절과 관성 유지에 의미 부여 |
| 스태미나·미끄러짐 수치와 단계 갱신 | 실패 원인과 회복 기회를 명확히 함 |
| 홈에서의 부분 추락 회수 | 작은 실수를 곧바로 회차 종료로 만들지 않음 |
| 돌턱과 진흙·젖은 바위 | 지형별로 다른 입력 판단 제공 |
| 전용 Debug Mountain과 F3 | 동일 코스에서 물리 변경을 재현·비교 |
| 1920×1080 기준 화면과 최소 HUD | 현재 상황은 읽히되 전체 진행률은 감춤 |
| 이전 최고점의 돌탑 흔적 | 최고 기록을 세계 안에서 표현 |
| 스태미나·Slip에 반응하는 소리 | 숫자 외의 판단 단서 제공 |

이미 구현한 수제 Chunk 조합과 맑음·비는 유지한다. 새 회차에는 v0.2용 물리를 적용하고 기존 저장의 진행 중 회차는 당시 산과 물리로 이어 간다. Debug Mountain은 일반 회차와 저장·기록을 분리한다.

## 이번 빌드의 수치와 해석

- 기본 추진력 2.6, 중력 계수 3.0, 최대 전진 속도 1.8m/s를 사용한다. 명세의 밀기 1.0은 행동 간 상대 기준으로 해석하고 실제 가속도 단위는 함께 튜닝했다.
- 0.45~1.2m/s에서는 추진력 ×1.1, 스태미나 소모 ×0.8, Slip 누적 ×0.9를 적용한다.
- 0~0.15m/s 출발에서는 중력과 구름 저항에 필요한 힘을 ×1.25로 계산한다. 1.5m/s 초과에서는 제어 효율 ×0.9, Slip 누적 ×1.4를 적용한다.
- 고난도는 **난이도 4 이상**으로 정의하고 새 산에서는 3연속 배치를 금지한다. 같은 Chunk 연속과 같은 지형 4연속도 검사한다. 기존 세대의 저장 배열은 바꾸지 않는다.
- 바위·자갈·진흙·젖은 바위를 사용한다. 이전 흙 지형은 기존 저장 호환용으로 유지한다. 비는 지정된 노출 구간에 접지력 ×0.85를 적용한다.
- 돌턱은 현재 접지력을 반영한 기본 힘의 ×1.6을 요구한다. 너무 빠를 때는 제어 효율이 떨어지므로 힘주기만 계속 유지하는 전략이 항상 통하지 않는다.
- 폭주 경계는 -4m/s 이하이며 발판 회수보다 우선한다. 폭주 전 후퇴가 홈을 통과하면 그 위치에서 멈추지만 스태미나를 즉시 채우지는 않는다.
- 저장 내부 버전 3은 산 정의와 함께 물리 계산의 잔여 시간, 폭주 경과 시간, 돌턱 통과 상태를 보관한다. 이전 세대 1·2는 기존 물리 분기로 재개한다.

테스트 코스는 98m이며 평지 → 20° 경사 → 안전 발판 → 자갈 30° → 돌턱 → 35° 경사 → 좁은 발판 → 젖은 바위 30° 순서다. 독립 자동 조작에서는 약 90초에 통과했다. 사람이 같은 시간에 통과한다는 보장은 아니다.

## 이후로 남기는 항목

- 호흡 타이밍 입력 보너스, 반동 기술의 특수 보너스, 오목·볼록 곡선 지형, 부서지는 발판
- 예고 강풍, 낙석, 얼음, 고도별 세부 환경·가짜 정상
- 기억, 스탯·능력형 성장, 이벤트, 철학, 서사와 엔딩
- Web·Mobile 내보내기와 터치 입력
- 역할별 Scene/Controller의 전체 구조 분리

호흡의 소리·캐릭터 피드백은 이번에 추가하지만 내쉬는 시점의 Shift 보너스는 새 명세 Phase 2 항목으로 구분한다. 현재 모듈을 확장하고 실제로 필요해지는 시점에 책임을 나눈다.

## 다음 개발 단계의 조건

명세 107번의 **10명 플레이 테스트**로 A~E 중 4개 이상을 충족하는지 확인한 뒤 기억·성장을 진행한다. 자동화 테스트는 물리·저장·렌더링의 오류를 검증하며, 이 조건을 대신 충족하지 않는다.

진행 방법과 빈 기록표는 [플레이 테스트 기록](playtest-v02.ko.md)에 있다.
