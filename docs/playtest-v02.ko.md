# v0.2 플레이 테스트 진행·판정 안내

**현재 실제 참가자 테스트는 미실시다.** 배포 파일, 기록 도구와 자동화 테스트는 준비 과정이며, 사람의 플레이 결과를 대신하지 않는다. 아래 절차로 실제 참가자 10명의 관찰 기록을 수집한다.

## 배포와 시작

1. Windows 실행 파일이 포함된 배포 ZIP과 [참가자 안내](playtest-participant.ko.md)를 전달한다. 참가자에게 고유 번호 01~10을 배정한다.
2. ZIP을 모두 압축 해제하고 `Playtest.cmd`를 실행하게 한다. 엔진 설치는 필요 없다.
3. 같은 참가자 번호로 연습 코스(practice)를 먼저 플레이하고, 일반 코스(normal)를 진행한다. 연습 기록과 일반 기록은 분리된다.
4. 새 세션(new)은 새로운 기록 폴더에서 시작한다. 중단한 세션은 같은 번호·코스의 이어하기(resume)로 계속한다. 다른 사람의 저장 파일을 공유하지 않는다.

일반 코스는 비교를 위해 같은 초기 조건을 사용한다. 연습은 고정 디버그 코스를 사용한다. 참가자에게는 총 산 길이나 디버그 수치를 설명하지 않으며 F3 화면은 끈다. 기능 문제를 조사할 때만 별도로 확인한다.

배포 대상은 Windows 10/11 x64다. 서명되지 않은 테스트 빌드이며 모든 PC 호환성을 확인한 것은 아니다. 실행 문제가 있으면 오류 내용과 로그를 회수한다.

## 관찰 순서

조작 키만 중립적으로 설명한다. **Shift 사용 전략, 발판 공략법, 기대하는 답은 미리 알려 주지 않는다.** 참가자용 안내에도 A~E의 구체적인 성공 조건을 싣지 않는다.

1. 연습에서 입력과 화면을 이해하는지 확인한다. 기술적 장애만 도와주고 조작 정답은 제시하지 않는다.
2. 일반 코스에서 등반·실패·재시도를 관찰한다. 참가자가 말한 내용은 가능한 그대로 기록한다.
3. 복구 순간과 목표를 잡는 행동을 기록한다. 필요하면 플레이 후 “그때 무엇을 하려고 했나요?”처럼 답을 유도하지 않는 질문을 한다.
4. 다른 참가자의 실제 추락 장면을 보여줄 수 있다면, 반응과 발언을 기록한다. 관전 기회가 없으면 E는 `unknown`으로 남긴다.
5. 일반 코스 종료 후 표시되는 질문에 실제 경험과 근거를 입력한다. 연습 후에는 기술적 문제·자유 의견만 받으며 A~E 질문은 하지 않는다. A~E 문항을 읽은 이후의 재시도는 사전 노출이 있었음을 자유 의견에 남긴다.

원격 참가자가 직접 작성한 답변은 `observation_source: self_report`인 자기보고다. 이를 진행자의 직접 관찰로 표현하지 않는다. 진행자가 현장에서 직접 관찰하여 기록할 때만 실행 도구의 `-ObservationSource facilitator_observation` 옵션을 사용한다. 보고서에도 기록 출처가 표시된다.

## 관찰 항목

| 코드 | 명세의 성공 기준 | 기록할 근거 |
|---|---|---|
| A | Shift를 계속 누르면 위험하다는 것을 자연스럽게 이해 | 실제로 힘주기를 조절한 순간과 본인 설명 |
| B | 한 번 이상 미끄러진 돌을 직접 복구 | 복구 위치·상황·사용한 입력 |
| C | 다음 발판을 작은 목표로 삼음 | 발판을 언급하거나 목표로 삼은 행동 |
| D | 실패 후 한 번 더 하고 싶어 함 | 유도 없이 재시도했는지와 이유 |
| E | 다른 사람의 추락 장면도 재미있게 느낌 | 관전 중 행동·발언 |

각 항목은 `observed`(관찰됨), `not_observed`(관찰 안 됨), `unknown`(판단 보류) 중 하나와 짧은 근거로 기록한다. 관찰 기회가 없거나 기억이 불확실하면 `unknown`을 사용한다. 부정적 반응, 불공정하게 느낀 순간, 막힌 위치도 자유 의견에 남긴다. 참가자의 긍정적인 답을 유도하거나 추정으로 빈칸을 채우지 않는다.

## 회수할 파일

참가자가 **playtest-results 폴더 전체를 직접 압축하여 전달**하도록 요청한다. 자동 전송 기능은 없다. 폴더에는 참가자 번호·코스·세션별 `session.json`, `observations.json`, `save.json`, `godot-<시각>-<식별자>.log`가 들어 있다. 개인 이름이나 연락처는 요구하지 않는다.

여러 참가자의 폴더를 한 수집 폴더 아래 모은다. 참가자 번호는 중복 배정하지 않는다. 같은 참가자가 여러 번 테스트했다면 모든 원본을 보관한다.

## 집계

진행자의 **프로젝트 폴더**에서 다음 명령을 실행한다. 참가자 배포 ZIP에는 집계 도구가 포함되지 않는다. 입력 폴더는 실제 회수한 결과가 있는 위치로 바꿀 수 있다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\summarize-playtest.ps1 -InputDirectory .\playtest-results
```

기본 보고서는 입력 폴더의 `summary.md`에 생성된다. `-OutputPath`로 저장 위치를 지정할 수 있다. 원본 JSON은 수정하지 않는다.

집계 규칙:

- 일반 코스의 완료된 `observations.json`만 집계한다. 연습 기록과 완료 시각이 없는 기록은 제외한다.
- 참가자별 **가장 최근에 완료된 한 세션의 A~E 전체**를 사용한다. 더 오래된 세션에서 유리한 항목만 골라 합치지 않는다. 최신 세션의 `unknown`도 그대로 유지한다.
- 동일한 완료 시각이면 파일의 전체 경로를 기준으로 정렬하여 마지막 파일을 사용한다. 선택된 세션과 제외된 중복 수를 보고서에 명시한다.
- 보고서에는 실제 집계된 참가자 수, 항목별 세 상태의 인원수, 참가자별 근거를 표시한다. 참가자 번호는 01~10으로 유지한다.
- 선택된 기록의 빌드 ID와 게임 버전을 표시한다. 빌드가 다르면 항목별 집계를 따로 제시하며 하나의 실험으로 합산하지 않는다. 빌드 미기재 기록도 별도로 표시한다. 같은 참가자의 이전 빌드 기록까지 비교하려면 원본 폴더를 빌드별로 나누어 각각 집계한다.
- 잘못된 JSON이나 지원하지 않는 형식은 별도로 보고한다. 파일이 없으면 실제 참가자 수는 0명이다.

## 판정

명세는 **10명 기준 A~E 중 4개 이상**을 요구하지만, 각 항목을 성공으로 인정할 참가자 비율은 정하지 않았다. 따라서 도구는 항목별 인원수와 근거만 집계하며 **자동 통과 판정을 내리지 않는다.** 판정 기준을 별도로 합의한 뒤 실제 결과를 검토한다.

관찰이 부족한 항목은 추가 관찰하고, 손맛 문제가 드러난 항목은 핵심 조작을 수정한 뒤 재검증한다. 실제 플레이 검증이 끝나기 전까지 기억·성장·이벤트·철학 엔딩 개발을 보류한다.
