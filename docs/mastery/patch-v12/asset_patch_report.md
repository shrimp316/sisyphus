# 숙련 석판 v1.2 에셋 수정 패치 적용

사용자가 제공한 `SISYPHUS_mastery_assets_v1_2_PATCH_ONLY.zip`의 11개 PNG를 같은 경로에 원본 바이트 그대로 교체했다. 나머지 120개 PNG는 기존 v1.1 ZIP과 SHA-256이 일치한다. 이전 석판 프리뷰 결과와 v1.1 원본 패키지는 변경하지 않았다.

## 교체 및 보존

- 캐릭터 밀기 개별 프레임 5개: 248×200 유지.
- 밀기 시트 1개: 1488×200 유지.
- 특별 플레이스홀더 5개: 128×128 유지.
- 교체 전 11개 원본은 [originals.zip](originals.zip)에 동일 경로/동일 바이트로 보관했다. 재실행 시 백업을 덮어쓰지 않는다.
- [비교 화면](comparison.html)은 두 PNG를 원래 바이트의 data URL로 표시한다. 체크 배경은 HTML 스타일이며 PNG를 수정한 것이 아니다.
- [기계 검증 결과](../../../tests/mastery/results/v12-patch/asset_audit.json): **149 PASS / 0 FAIL**, 11개 패치 일치, 120개 비대상 보존, 시트 push01~05 셀과 개별 프레임 픽셀 일치.

## 확인한 차이

첫 밀기 프레임의 알파 경계는 기존 `(69, 0, 248, 167)`에서 `(21, 34, 239, 193)`으로 바뀌었다. 기존 프레임은 상단·오른쪽 경계에 닿았고, 수정본은 캐릭터가 이미지 안에 들어온다. 나머지 프레임도 패키지의 새 포즈로 교체됐다. 새 포즈와 석문 접촉 위치는 실제 Godot 화면에서 별도로 검증해야 한다.

특별01의 알파 경계는 `(1, 1, 127, 91)`에서 `(14, 12, 117, 117)`로 바뀌었다. 원본의 위쪽에 치우친 도형 대신 새 원형 금빛 문양을 사용한다. 이 변경은 UI 원화 교체이며 특별 노드의 능력·문자·비용을 확정하지 않는다.

**알파 해석 정정:** 일부 이미지 뷰어가 투명 픽셀 뒤의 RGB까지 보여 주어 원본 특별01 하단에 흰 글자가 보이는 것처럼 해석할 수 있다. 실제로 y110 이후 흰색 RGB 픽셀 46개는 모두 alpha=0이며 표시되지 않는다. 따라서 이를 인게임에서 관찰한 글자 누출이라고 주장하지 않는다. 비교 검사는 검정·흰 배경에 알파 합성했을 때의 변화도 별도로 기록한다.

시트 첫 셀 역시 빈 슬롯이 아니다. 첫 셀 알파는 기존 idle PNG와 동일하고, RGBA 265픽셀에 작은 RGB 차이가 있다. 뒤의 5개 셀은 새 개별 밀기 프레임과 정확히 일치한다. 현재 석문 연출은 별도 idle PNG와 개별 push 프레임만 사용하므로 시트의 첫 셀 차이는 현재 실행 경로에 사용되지 않는다.

최초 검사에서 뷰어 표시를 근거로 첫 셀이 비어 있다는 잘못된 기대를 검사에 넣었다. 그 한 항목의 실패를 [초기 기록](../../../tests/mastery/results/v12-patch/initial_audit_incorrect_sheet_assumption.json)에 보존했다. 실제 알파 값을 확인하여 검사를 바로잡았으며, 이후 적용 재실행과 비적용 검사 모두 149개가 통과했다. 재실행에서 추가 교체는 0개였다.

## 재현

```powershell
python -X utf8 tests/mastery/audit_patch_assets.py --apply
python -X utf8 tests/mastery/audit_patch_assets.py
```

기본 원본/패치 경로는 사용자 Downloads의 제공 파일이다. 다른 위치는 `--original`과 `--patch`로 지정한다. 허용된 11개 경로 이외의 payload, 중복 ZIP 항목, 경로 탈출, 알 수 없는 기존 PNG 변경을 만나면 교체 전에 거부한다. 새 이미지를 리사이즈하거나 재압축하지 않는다.
